# scripts/dev — manual smoke-test driver

Three scripts drive a local dugdale via the `letts` CLI:

1. `./run.sh` — start the daemon (foreground).
2. `./apply.sh` — reconcile mission_dir and lanes via `letts apply`.
3. `./dispatch.sh <mission> [input] [lane]` — dispatch and follow via `letts run`.

The original curl-based versions are gone; if you need raw HTTP debugging,
invoke curl manually using `lib.sh` which still defines `DUGDALE_URL` and
token helpers (`curl_admin`, `curl_disp`, `gen_uuidv7`).

## Quickstart

In one terminal — start the daemon:

```sh
./scripts/dev/run.sh
```

Watch for `dugdale started listen=127.0.0.1:7180 data_dir=/tmp/letts-dev/data`.

In another terminal — apply config (one-time per data_dir reset) and
dispatch a mission:

```sh
./scripts/dev/apply.sh
./scripts/dev/dispatch.sh hello
./scripts/dev/dispatch.sh progress
./scripts/dev/dispatch.sh with_output
./scripts/dev/dispatch.sh fail
```

`apply.sh` and `dispatch.sh` build a temp letts.yaml from
`scripts/dev/letts.yaml` with the `__MISSION_DIR_PLACEHOLDER__` token
replaced by an absolute path (defaults to `scripts/dev/missions`).

Each `dispatch.sh` invocation:

1. Resolves host=`local` and lane against the temp letts.yaml.
2. POSTs to `/v1/dispatch` (UUIDv7 is generated by `letts run`).
3. Streams `/v1/missions/{id}/events?follow=true` until the terminal
   `done` event, logging `[event] …` lines to stderr.
4. Pretty-prints the `return` JSON on stdout.

Exit code: 0 on success, 1 on `failed`, 124 on `--wait-timeout`, 125 on
abnormal (killed/timeout/oom/crashed/lost).

## Knobs

```sh
DUGDALE_URL=http://127.0.0.1:7180  # daemon base URL (curl/lib.sh only)
DUGDALE_DISP_TOK=dev-disp-token    # /v1/dispatch and read endpoints
DUGDALE_ADMIN_TOK=dev-admin-token  # /v1/admin/* and control endpoints
MISSION_DIR=/path/to/missions      # apply.sh and dispatch.sh — overrides default
```

The matching values are also baked into `scripts/dev/letts.yaml` (tokens)
and `scripts/dev/dugdale.yaml` (listen address and tokens).

## Sample missions

`scripts/dev/missions/`:

| Script           | What it exercises                                     |
|------------------|-------------------------------------------------------|
| `hello.sh`       | stdout, stderr, and fd3 success with `return` payload |
| `progress.sh`    | fd3 progress events streamed via `/events`            |
| `with_output.sh` | writes `work/out/result`, registers via `output_file` |
| `fail.sh`        | fd3 fail event and non-zero exit code                 |

## Useful endpoints

```sh
# health
curl localhost:7180/v1/healthz

# version
curl localhost:7180/v1/version

# Prometheus metrics (no auth)
curl localhost:7180/v1/metrics

# inspect lanes (Bearer disp token)
curl -H "Authorization: Bearer dev-disp-token" \
    localhost:7180/v1/lanes

# list recent missions
curl -H "Authorization: Bearer dev-disp-token" \
    'localhost:7180/v1/missions?limit=10'
```

## Reset state

```sh
rm -rf /tmp/letts-dev/data && mkdir -p /tmp/letts-dev/data
```
